# Harbor Container Registry

This directory contains Ansible playbooks for deploying and managing Harbor container registry on the Thinkube platform.

## Installation

Harbor is a core component. The Thinkube installer installs it by running
`00_install.yaml`, which runs `10_deploy.yaml`, `11_install_podman.yaml`,
`12_configure_thinkube.yaml` and `17_configure_discovery.yaml` in that order.
It is not installed on its own.

## Overview

Harbor is an open-source container registry that provides:
- Container image storage and distribution
- OIDC authentication integration with Keycloak
- Image vulnerability scanning
- Role-based access control
- Image replication
- Project isolation

## Playbooks

### 00_install.yaml
Runs the playbooks below in order: 10, 11, 12, 17.

### 10_deploy.yaml
Main deployment playbook that:
- Creates Keycloak OIDC client for Harbor authentication
- Deploys Harbor using Helm chart
- Configures OIDC authentication
- Sets up persistent storage for all components

### 11_install_podman.yaml
- Installs podman and enables rootless podman for the system user
- Installs QEMU for multi-architecture builds (amd64/arm64)

### 12_configure_thinkube.yaml
Post-deployment configuration that:
- Creates the project named by `harbor_project` in Harbor
- Creates a system-level robot account for Kubernetes deployments
- Creates the `harbor-pull-secret` pull secret in the default namespace
- Stores credentials in ~/.env

### 17_configure_discovery.yaml
- Creates the service-discovery ConfigMap that describes Harbor's endpoints

Public images are mirrored into Harbor by
`../harbor-images/13_mirror_public_images.yaml`, not by this folder.

### 18_test.yaml
Comprehensive test playbook that verifies:
- Kubernetes resources are properly deployed
- Harbor API is accessible
- OIDC authentication is configured
- Registry operations (push/pull) work correctly

### 19_rollback.yaml
Cleanup playbook that:
- Removes Harbor Helm release
- Deletes Harbor namespace
- Cleans up temporary files

## Dependencies

- Kubernetes (kubeadm) control plane and worker nodes
- Wildcard TLS certificate in the default namespace (`infrastructure/acme-certificates`)
- Gateway API gateway (`infrastructure/gateway-api`)
- Keycloak (for SSO)

## Required Variables

These are set in `inventory/group_vars/k8s.yml`:

```yaml
# Registry configuration
harbor_registry: "registry.{{ domain_name }}"
harbor_namespace: "registry"
harbor_release: "harbor"
harbor_project: "thinkube"
harbor_robot_name: "thinkube"
harbor_admin_user: "admin"

# Admin configuration (inherited from global)
admin_username: "tkadmin"
# admin_password is provided via ADMIN_PASSWORD environment variable
```

Storage is not set from the inventory. `10_deploy.yaml` sets it in the Helm
values: storage class `k8s-hostpath` for every volume; registry 500Gi,
database 10Gi, Trivy 10Gi, job logs 5Gi, Redis 2Gi. The inventory also
defines `harbor_registry_size` and `harbor_database_size`, but no Harbor
playbook reads them.

## Environment Variables

- `ADMIN_PASSWORD`: Required for Keycloak authentication during deployment
- `HARBOR_ROBOT_TOKEN`: Generated by 12_configure_thinkube.yaml, required for image mirroring

## Usage

1. Deploy Harbor:
   ```bash
   cd ~/thinkube
   export ADMIN_PASSWORD="your-admin-password"
   ./scripts/run_ansible.sh ansible/40_thinkube/core/harbor/10_deploy.yaml
   ```

2. Configure thinkube project:
   ```bash
   ./scripts/run_ansible.sh ansible/40_thinkube/core/harbor/12_configure_thinkube.yaml
   ```

3. Test the deployment:
   ```bash
   ./scripts/run_ansible.sh ansible/40_thinkube/core/harbor/18_test.yaml
   ```

## Post-Deployment

After successful deployment:

1. Access Harbor UI at https://registry.<domain_name>
2. Login using Keycloak SSO with your admin credentials
3. The 'thinkube' project is ready for use
4. Robot credentials are stored in ~/.env

## Registry Usage

### Docker/Podman Login
```bash
docker login registry.<domain_name>
# Use robot credentials from ~/.env or SSO credentials
```

### Push an Image
```bash
docker tag myimage:latest registry.<domain_name>/thinkube/myimage:latest
docker push registry.<domain_name>/thinkube/myimage:latest
```

### Pull an Image
```bash
docker pull registry.<domain_name>/thinkube/myimage:latest
```

### Kubernetes Pull Secret
The deployment creates a pull secret in the default namespace:
```yaml
imagePullSecrets:
  - name: harbor-pull-secret
```

## Troubleshooting

### Check Harbor Status
```bash
kubectl get pods -n registry
kubectl get svc -n registry
helm list -n registry
```

### View Logs
```bash
kubectl logs -n registry deployment/harbor-core
kubectl logs -n registry deployment/harbor-registry
```

### Verify OIDC Configuration
```bash
curl -I https://registry.<domain_name>
# Should redirect to Keycloak for authentication
```

## Rollback

To completely remove Harbor:
```bash
./scripts/run_ansible.sh ansible/40_thinkube/core/harbor/19_rollback.yaml
```

This will:
- Remove the Helm release
- Delete the namespace
- Clean up temporary files

## ARM64 Support

Harbor v2.14.0 does not provide official ARM64 container images. On an
arm64 control plane, `10_deploy.yaml` overrides the images in the Helm
values. On amd64 it uses the official goharbor images.

### Image Source

| Component | ARM64 image |
|---|---|
| core | `ranichowdary/harbor-core:latest` |
| portal | `ranichowdary/harbor-portal:latest` |
| jobservice | `ranichowdary/jobservice-harbor:latest` |
| registry | `ghcr.io/thinkube/thinkube-harbor-arm64/harbor-registry-arm64:v2.14.0` |
| registry controller | `ranichowdary/harbor-registryctl:latest` |
| database | `ranichowdary/harbor-db:latest` |
| redis | `valkey/valkey:latest` |
| trivy | `ghcr.io/thinkube/thinkube-harbor-arm64/harbor-trivy-adapter-arm64:v2.14.0` |

The `ranichowdary` images come from https://hub.docker.com/u/ranichowdary
(author of Harbor's multiarch-platform-support branch). The two `ghcr.io`
images are built in https://github.com/thinkube/thinkube-harbor-arm64.

### Patches on arm64

After the Helm install, on arm64 only, `10_deploy.yaml` patches two
workloads:
- `harbor-portal` deployment: the command is set to `nginx -g "daemon off;"`
  to fix a duplicated command.
- `harbor-trivy` statefulset: the command is set to
  `/home/scanner/bin/scanner-trivy` to bypass the x86 entrypoint.

## Notes

- Harbor includes its own PostgreSQL database and Redis instance
- Images are stored on persistent volumes using the configured storage class
- OIDC authentication is required; local user authentication is disabled
- The wildcard TLS certificate is copied from the default namespace
- Robot accounts are used for automated registry operations
- All installation-specific values must be defined in inventory
- Environment variables follow the project standard: ADMIN_PASSWORD, AUTH_REALM_PASSWORD
